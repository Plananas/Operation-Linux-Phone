# TREND OS — technical reference (for Claude)

Current state, by topic. History lives in git; user guide in `README.md`.

## 1. Device
SM-G318H `vivalto3mveml3g` · Spreadtrum **SC8830** (2× Cortex-A7 ARMv7+NEON, core 1 hot-plugs) · 465 MB RAM · `/data` 2.2 GB · stock Android 4.4.4 · kernel **3.10.17 Samsung** · secure boot **off**.
Partitions: SBOOT p1, SBOOT2 p2, PARAM p16, **KERNEL p20** (boot img), system p24, **userdata p26**; SPL in `mmcblk0boot0`. PIT: `backup/pit.txt`.

## 2. Current state
- Boot image: **`firmware/trendos/boot-native8.img`** = **our own kernel with Bluetooth** (§7 Kernel) + stock DT + our ramdisk. Previous: `boot-native7.img` (our kernel, no BT), `boot-native6.img` (stock Samsung kernel). RECOVERY (p21) also holds a TREND OS test kernel (stock recovery: `firmware/stock/recovery.img`). Ramdisk `init` → charger mode? `/bin/charger` : logo + `bootanim` → `switch_root` to **Alpine 3.24 at `/data/alpine`** (OpenRC). Android never starts.
- OpenRC default runlevel: `usbnet sshd bootscreen wifi timesync dbus btuart bluetooth btaudio local`. Shell = `bootscreen` service (supervise-daemon) → `/usr/local/bin/trendos.py` → package `/usr/local/lib/trendos/tos` + `libtrend.so`.
- Storage: `userdata` (p26) holds only `alpine/` (TREND OS root) + `native-init.log` (Android's files deleted 2026-11-03, ~2 GB free). Android's `system` (p24) still intact but unused (Wi-Fi fw + FM patch already copied to `/data/wifi`, `/data/bt`).
- Network: **Wi-Fi** (default route, auto-connects) + **USB RNDIS** (phone 192.168.42.129, laptop .1, NM conn `phone-usb`, metric 100 backup). SSH key-only, root.
- Apps: home carousel = welcome cube, Calculator, Radio, Music, Clock, SSH, Files, Settings → [Wi-Fi, Bluetooth]. Spotify shelved (§7).
- Time: timezone Europe/London (`tzdata`, `/etc/localtime`). OpenRC **`timesync`** = busybox ntpd as root (Alpine's `ntpd` service can't work: it relies on ambient capabilities, not in 3.10); `-S ntp-synced` writes `/tmp/ntp-last-sync`; RTC saved at shutdown (`conf.d/hwclock` clock_systohc).

## 3. Gotchas (read before touching)
**Charger-mode boot**: on the one logged boot with `androidboot.mode=charger` (2026-11-04), Wi-Fi (`wl_android_wifi_on failed (-35)`), Bluetooth (no hci0) and so FM (`I/O error`) stayed down; a normal `reboot` brought them back. Cause not investigated.
**Boot image**: `reboot recovery` boots RECOVERY (p21) and that flag is **sticky** across power-cycles until a normal reboot (`syscall(88,…,"normal")`, see `kernel/test-in-recovery.sh`); `reboot download` = Download mode without buttons. Stock boot.img has a Spreadtrum DT *after* the ramdisk (`dt_size`); abootimg drops it → no boot. Always repack with `bootimg/repack_keep_dt.py`. Ramdisk cpio must be root-owned → `bootimg/mkramdisk.py`. Bootloader passes `androidboot.mode=charger` when powered on by a charger (`poweroff` with USB in → charger boot). First 8 MB (SBOOT/SBOOT2) write-protected; Samsung power-on logo can't change.
**Display** `/dev/fb0` 480×800, 3 pages, byte order **RGBX**. Pan returns immediately → always `FBIO_WAITFORVSYNC`, triple-buffer, never write the visible page. **Never write 0 to backlight** (use 160). Pan/read/write = EPERM while asleep. Wake: wake lock → `mem` → `on` > `/sys/power/state` → wait `/sys/power/wait_for_fb_wake` → pan.
**Input**: touch `/dev/input/event1` (MT protocol B, screen px; KEY_BACK 158). The kernel drops repeated values per slot, so injected gestures must vary X and Y or a freshly restarted shell keeps y = 0 and ignores taps (`tools/phone/drive.py` handles this). Keys `event0` (HOME 102, POWER 116, VOL). `input_event` = `llHHi`.
**Audio**: card numbers change per boot → always by name: `amixer -c sprdphone`, `aplay -D hw:CARD=sprdphone,DEV=0`. Route with `/usr/local/sbin/audio-speaker`; `VBC Switch` must be `ap`.
**CPU**: compute /proc/stat per core (core 1 hot-plugs). **Sockets**: `ANDROID_PARANOID_NETWORK` → only root/gid 3003 may open sockets.
**SSH server**: `/etc/ssh/sshd_config.d/10-phone.conf` listens on USB (192.168.42.129) and 127.0.0.1 only, not Wi-Fi; key login only. Kernel has no `/proc/PID/io` or `ss`, so the SSH app's activity trace is sshd CPU time + pts timestamps, not bytes.
**Wi-Fi** (bcmdhd built in, nl80211 only): `/usr/local/sbin/wifi-up` loads fw from `/data/wifi`; **must `iw dev wlan0 set power_save off`** or DHCP never completes. `wifi-connect` (SSH, prompts), OpenRC `wifi` service autoconnects; creds `/etc/wpa_supplicant/wpa_supplicant.conf`.
**Font**: VT323 has **no arrows/geometric glyphs (↓↑○●▶✓)** — use ASCII or draw shapes. `gfx.font(size)` takes DejaVu-equivalent px. 3D ASCII atlas uses DejaVu (`gfx.art_font`).
**Perf**: home screen ~10 % of one core, Radio live ~25 %. `to_rgbx` costs ~14 ms per app frame, 9.5 of it in PIL's `tobytes`, so C can't fix that: use `canvas`. Not yet moved: Clock, Wi-Fi, Bluetooth, SSH, power menu. Open question: a shell that had been through several apps used 24.9 % with Calculator idle, against 8.1 % fresh, so some app seems to leave work running after it closes (Radio alone doesn't; not traced). The A7 is in-order and its prefetcher is weak: hot full-frame loops need NEON *unrolled ×4* + `__builtin_prefetch` (transition `slide_frame`: plain C 10.5 ms → 4.5 ms/frame; NEON without unrolling barely helps, and a benchmark with constant args inlined lies). Plain copy of a frame ≈ 2.7–5 ms. Avoid per-frame full-frame copies in Python. Measure via `utime+stime` from `/proc/PID/stat`.

## 4. Code map
Repo layout: see *What's in this folder* in `README.md`. `overlay/` mirrors the phone filesystem. Package root `usr/local/lib/trendos/tos/`:

| File | Role |
|---|---|
| `config.py` | all constants: `W=480 H=800 TOP=66 APP_H`, `PALETTE` + colour indices (`RED GREEN … CYAN ORANGE WHITE`), `ACCENT`, `SHADES`, timings |
| `shell.py` | main loop; modes launcher/app/transition/power/halt/asleep; region cache per page keyed by `app.key()` |
| `launcher.py` | `Entry(model, app=None, opens=None, name=None, phase=…)`; `default_entries()`, `settings_entries()` |
| `apps/` | `base.App`, then one folder per app: `<app>/app.py` holds the class, `<app>/__init__.py` exports it. `calculator/` and `music/` (thin wrappers: the apps are C, in `native/libtrend/src/apps/<app>/`, §7 Music), `wifi/` (threads + keyboard example), `radio/` (hardware worker thread, live 30 fps numpy drawing), `clock/` (7-segment glow digits, alarms via `background()`), `ssh/` (SSH live viewer, data from `tos/hw/sshmon.py`: /proc/net/tcp, sshd processes, /var/log/messages; view only), `spotify/` (shelved) |
| `render.py` 3D for apps | `draw_view(buf, shape, m9, K, cols, rows, x, y, tiles)` draws a Shape into any cell viewport (K ≈ cols×1.5 fills it); `card_tiles(y, PANEL, SCAN, card_y0)` = ASCII tiles on a card's background; `MINI` 5×7 tiles; `matrix(tilt, a, b, c)` pose. Shapes: `Shape.combine`, `.transformed(R, t)`; for moving parts update `shape.pts/fnrm/fcen` in place (see `Clock3D`). Palette adds `DIMGREEN`. Shell draws each app's launcher icon as a spinning badge in its title bar (`App.icon_shape`, set by `Entry`); `tos/flight.py` flies it between the carousel and the badge on every app open/close (cell-size ladder 8×12→5×7, object cut out of the launcher snapshot, badge left out of the sliding app frame) — automatic for any app opened from a carousel. |
| `native.py` | the Python/C boundary: wraps libtrend (`slide`, `scale`, `blend`, `mesh_draw`, `scope_frame`, `terrain_draw`...); numpy arrays in, no pointers out |
| `canvas.py` | fast 2D straight into RGBX arrays via libtrend: `blank`, `fill_rect`, `stroke_rect`, `fill_round_rect`, `fill_stripes`, `text`, `text_width`, `text_strip`. Use for anything redrawn often. Rectangles are half-open and PIL's are inclusive |
| `ui.py` | shared look: palette (`PANEL MID DIM GHOST FLARE ERR…`), `native_card()` (fast), `card()`, `key_image()`, `Keys` (PIL) — use it for new apps |
| `hw/` | the devices; imports nothing above `config`. `fb` `inputdev` `fm` `btchip` `bluetooth` `audio` `sshmon` (rows below) |
| `hw/fm.py` | FM radio driver (`FM().on/tune/rssi/off`, `set_volume`); CLI `/usr/local/sbin/fmctl` |
| `hw/btchip.py` | the BCM43430A1 BT/FM chip: rfkill power, patch, 3 Mbaud, BD address; `RawUart` (no BlueZ) or `HciSocket` (via hci0) — FM uses whichever applies |
| `hw/bluetooth.py` / `hw/audio.py` | `BtCtl`: long-lived `bluetoothctl` as pairing agent + parsed device list; `audio.bt_sink()` = connected A2DP device, `bt_device(mac)` = ALSA name |
| `models/` | 3D icons: `shape.py` (`Shape`, `boxes`, `extrude`, `arc`, `relief`), `icons.py` (`@model(name, colour)`), `registry.py` |
| `keyboard.py` | on-screen keyboard (`Keyboard(on_done, on_cancel, text)`, `.touch/.key/.render`, `KB_Y`) |
| `gfx.py` | `font`, `text_strip`, `canvas`, `to_rgbx`, `blit`; glyph cache `draw_text(im,x,y,s,size,col)` / `text_len` (use for big or often-redrawn text) |
| `hw/fb.py` `hw/inputdev.py` `transition.py` `power.py` `stats.py` `title.py` `boot.py` | framebuffer · evdev · Slide anim · power menu · stats panel · typewriter title · boot handover/sound |

**C** lives in `native/` (rules and style: `native/README.md`): `native/libtrend/` → `libtrend.so` (built on phone by deploy; `pixels` `draw` `mesh` `viz` `expr` and `apps/<app>/`) · `native/player/` → `libtrendplay.so` (§7 Music) · `native/boot/` (`bootanim.c`, `fbpan.c`, `charger.c`, `*.armv7-static`). `tos/native.py` is the only Python file allowed to import ctypes.
Other: `/etc/init.d/{bootscreen,usbnet,wifi}` · `/usr/local/sbin/*` helpers · ramdisk init in `bootimg/ramdisk/`.

## 5. Adding an app (recipe)
1. **App** — `tos/apps/myapp/app.py`, plus `tos/apps/myapp/__init__.py` with `from .app import MyApp`:
   ```python
   from PIL import Image, ImageDraw
   from ...config import W, APP_H, ACCENT
   from ...gfx import font, to_rgbx
   from ..base import App
   class MyApp(App):
       name = "My App"                       # title bar + launcher label
       def on_open(self): ...                # optional: start hardware/threads (on_close stops them)
       def on_key(self, code, pressed): ...  # optional: volume keys 114/115; return True if used
       def background(self, now): ...        # optional: ~1/s even when closed/asleep; True = shell wakes the screen + brings app to front
       keep_awake = False                    # optional: True = no auto screen-off while open
       def touch(self, ev, x, y): ...        # ev "down"/"move"/"up", screen coords (y >= TOP)
       def key(self, now): return self.state # hashable; render() only runs when it changes
       def render(self, now):                # -> numpy RGBX array (APP_H, W, 4)
           im = Image.new("RGB", (W, APP_H)); d = ImageDraw.Draw(im)
           d.text((20, 20), "hello", font=font(28), fill=ACCENT); return to_rgbx(im)
   ```
   Draw with `tos/canvas.py` and `ui.native_card`, not PIL: a typical screen costs ~10 ms against ~50 ms. PIL is for one-off images. If a loop still shows up in a profile, move the whole loop into `native/libtrend`, since each Python-to-C call costs ~0.1 ms. Rules: keep `key()` cheap and stable when idle (that's what keeps CPU low); include time buckets (`int(now*30)`) only when animating. `render()` may run before `on_open` (launcher pre-renders apps). For animation: keep one persistent buffer, redraw only changed regions, and use whole-array numpy (uint32 views + lookup tables); per-pixel Python/PIL per frame is far too slow (each full app-area copy alone is ~5 ms). Measure on the phone before deploying. Slow work (subprocess, network) → daemon thread that updates state and bumps a version in `key()` (see `wifi.py`). Text input → `Keyboard` (see `wifi.py` connect mode). Back/Home/title-tap close the app automatically. Style: black bg, green-phosphor `ACCENT`, VT323, ASCII only — build screens from `tos/ui.py`. Add a 3D touch where it fits (house style: ASCII-shaded 3D): draw the 2D layer only when it changes, keep a copy, and each frame restore the 3D viewport from it and `draw_view(...)` into it (wifi.py `_draw_bars`, clock.py `_draw_3d`); include `int(now*15)` in `key()`. A once-a-second full PIL redraw (~45 ms) is fine; for 20–30 fps follow radio.py.
2. **Export** in `tos/apps/__init__.py`.
3. **Icon** — in `tos/models/icons.py` add `@model("myicon", COLOUR)` returning a Shape from `boxes([...], colour_by_axis=(…))` (blocky), `extrude(inside_fn, outlines, depth, colour)` (2D silhouette) or `relief(colour_at, depth)`. Fit within ~[-1.3, 1.3] x/y, flat front. Preview: `ssh phone 'cd /usr/local/lib/trendos && python3 -m tos.models myicon'`.
4. **Launcher** — `Entry("myicon", MyApp(), phase=(a, b, c))` in `default_entries()` (or `settings_entries()` for a setting; a sub-menu is `Entry(..., opens="name")`).
5. **Deploy** `tools/deploy.sh`, then check: `ssh root@192.168.42.129 rc-service bootscreen status`; logs via `logread`/supervise output. Screenshot + tap without hands: §6.
New OpenRC service: add `etc/init.d/X` to the overlay **and** to `FILES` in `tools/deploy.sh`, then `rc-update add X default` on the phone.

## 6. Procedures
- **Deploy userland**: `tools/deploy.sh [user@host]` (tar overlay → phone, build libtrend, restart shell). `SPOTIFY=1` re-enables Spotify.
- **Static C on phone**: `gcc -static -O2 -s -o X X.c [-lm]`.
- **Boot image**: on phone `trendos.py --boot-anim bootanim.bin`, `--boot-frame logo.rgbx`, `mkcharger.py charger.bin`; copy back; then on laptop
  `python3 bootimg/mkramdisk.py bootimg/ramdisk busybox.static rd.gz logo.rgbx=… bin/fbpan=… bin/bootanim=… bootanim.bin=… bin/charger=… charger.bin=…` →
  `python3 bootimg/repack_keep_dt.py firmware/stock/boot.img rd.gz firmware/trendos/boot-nativeN.img`. Flash: `dd of=/dev/mmcblk0p20 conv=fsync` on phone, verify sha256, reboot (fallback `heimdall flash --KERNEL img` in Download mode).
- **Rescue**: init falls back to RNDIS + `telnet 192.168.42.129` if Alpine fails or `/data/alpine/.native-disable` exists. BootROM: battery out, hold Vol-Up, plug USB → `1782:4d00` (`tools/bootloader/bootrom_hello.py`; flashing needs FDL1/FDL2, not obtained).
- **Phone tools**: `tools/phone/`: `bench.py` (frame costs + live shell CPU, run before and after a change), `drive.py` (walk the UI with injected input, screenshots), `shot.py` (screenshot), `mkchime.py` (soft chime for testing Music), `mkjungle.py` (synthesises the Music test song; ~2 min, the phone's 32-bit ints and memory limit it: watch for overflow in numpy integer arrays, and avoid transforms of the whole song). Copy to `/tmp` on the phone; run with `python3 -I`. Home returns to the first carousel item.
- **UI tests**: inject `input_event`s into event1 (SLOT 0, TRACKING_ID n, X, Y, SYN … TRACKING_ID -1) / event0 (keys). Screenshot = read `/dev/fb0` at `pan_y*480*4` (`/sys/class/graphics/fb0/pan`), as RGBX. Wake first (inject Home).

## 7. Subsystems
**FM radio** (works, analog): FM core inside BCM43430A1 BT combo, driven by vendor HCI `0xFC15 [reg, 0=w|1=r, data…]` over `/dev/ttyS0` 115200 RTS/CTS. Driver `tos/hw/fm.py`, CLI `fmctl on [MHz] | tune MHz | off`; patch `/data/bt/BCM43430A1.hcd` (auto-copied from /system). Headphones = antenna. Radio app: opening powers on (~4 s), closing powers off; dial/keys tune; vol keys = codec HP volume 0–15; visualiser = `arecord` of the codec line-in (`hw:CARD=sprdphone,DEV=0`, 16 kHz mono works while the analog path plays); state in `/var/lib/trendos/radio.json`. CPU ~35 % of a core live (20 fps), ~60 % while dragging.
- UART EIO until `rfkill0` toggled 0→1. Bring-up: reset → `0xFC2E` → send .hcd → reset → **`0xFC27` (12 zeros) sleep off** (else `close()` hangs, port wedged till reboot). Always `tcflush` before close.
- Regs: 0x00 power (1 FM, 3 +RDS) · 0x01 ctrl (0x04 stereo) · 0x05 audio (0x1c = DAC L+R; 0x02 mute) · 0x09 tune mode (1 preset, 2 seek) · 0x0a/0b freq = kHz−64000 LE · 0x0f RSSI · 0x12 flags · 0xf8 volume. Codec line-in path in `codec_on()`.
- **DON'T use digital FM** (`hw:sprdphone,4` / EXTDIGFM) — reboots the phone. Open: RSSI reads a flat ~170–185 across the whole band (no station found yet; antenna/headphones or RSSI meaning unverified) → no auto-seek yet; RDS (0x80); chip volume 0xf8.

**Kernel** (ours since 2026-11-03): Samsung source github.com/TechTex198/SM-G318H-Kernel-Source (3.10.17) in `tools/ext/kernel`, `kernel/build.sh` (GCC 4.7.3, Docker) → `firmware/trendos/boot-kernel-test.img`. Config = `vivalto3mveml3g_hw00_defconfig` + `kernel/trendos.config` (public defconfig is the Spreadtrum-Marlin board variant; ours has Broadcom: BCM4343 dhd, BCM BT rfkill/LPM, GPS BCM47520, zswap/vnswap; matched to stock `/proc/kallsyms`, remaining diffs = Samsung security hooks, MUIC debug UART, MAC-from-file). Patch `kernel/trendos-logo.patch`: sprdfb paints the boot frame (`kernel/bootframe.rgbx` ← `tools/bootloader/logo/sboot_logo.jpg`, via `mklogo_h.py`) into the bootloader's buffer at ~0.44 s → Samsung logo only ~1 s; always 3 fb pages (stock uses 2 in recovery mode). Test new builds with `kernel/test-in-recovery.sh`, install by `dd` to p20 + normal reboot.

**Bootloader (SBOOT logo) via BootROM** — paused, plan: own FDL1. BootROM (Vol-Up + USB) = `SPRD3`, runs any FDL1 at 0x50000000; spd_dump needs `tools/bootloader/spd_dump-sc8830-64byte.patch` (`SPD_CHUNK=64`: high-speed device, 64-byte bulk maxpacket). Public SC8830 FDL1 (zeallar/w_sprd_fdls, TD860 phone) hangs after exec (DDR init). Own SPL has the right DDR init but no USB. Read-only test: `tools/bootloader/bootrom-read.sh`.

**Bluetooth** (needs our kernel with BT, `trendos.config`): OpenRC `btuart` (`bt-up`: `btchip.boot_raw(3000000, efs address)` then `btattach -B /dev/ttyS0 -P h4 -S 3000000` → hci0), `bluetooth` (BlueZ 5.86 bluetoothd), `btaudio` (bluealsa, A2DP source+sink), `dbus`. Address `D0:87:E2:DB:B7:94` from efs `bluetooth/bt_addr` (copied to `/data/bt/bt_addr`; chip default is 43:43:A1:…). UART at 3 Mbaud works (needed for A2DP). Quirks: Alpine's `bluealsa` service segfaults — bluealsa reads past the stack top where env strings live, so OpenRC's tiny environment crashes it; `btaudio` passes an 8 KB `STACK_PAD` env var. bluealsa's storage dir is `/usr/var/lib/bluealsa`. Bluetooth app: Settings → Bluetooth (on/off, scan 20 s, pair = pair+trust+connect, connect/disconnect, forget). Radio streams to a connected A2DP device (line-in 44.1 kHz stereo → `aplay -D bluealsa:…`), wired headphones muted (still the antenna).

**Music**: all C. `native/libtrend/src/apps/music/` = touch and drawing, pure like Calculator: touches return a `tr_music_cmd`, render is a function of state + status + library. `native/player/` = `libtrendplay.so`, a thread that scans `/data/music`, decodes (libsndfile: MP3, FLAC, Ogg, Opus, WAV) and plays (ALSA). `apps/music/app.py` only passes commands from one to the other and supplies fonts. Separate library because it holds state and needs `alsa-lib-dev` + `libsndfile-dev` (deploy installs them): if it's missing the app says so and the shell is fine. Output: Bluetooth > headphones (`/sys/class/switch/h2w/state`) > speaker, routed with `audio-speaker` / `audio-headphones` each time the device opens, so after the Radio has changed the mixer too. Volume is software, 0-15. **The audio device is exclusive, so anything else that plays must call `audio.take_output()` first** (`hw/audio.py`): it pauses Music and closes the device; Clock and Radio do. Visualiser (`music_viz.c`, the second tab; `music_layout_of` places the shared title, seek bar and keys on each tab): abstract 3D in the icons' shaded ASCII, through `tr_mesh_grid` and the same tile atlas: a cube that kicks with the bass, 24 spectrum bars in a ring, 8 orbiting shards, and faint rays and ripples in the empty cells. Objects are rebuilt per frame, with positions snapped to a coarse grid for a PS1 shiver. 12 Goertzel bands come from `status.scope` (taken before the volume, so it works at volume 0, handy for silent testing). State is small; `advance` goes by the clock, so rendering the same moment for another page doesn't step it twice. **Don't encode MP3 with libsndfile on the phone** (armv7 Alpine): even a sine comes out with bursts of near-full-scale noise every frame, whichever decoder reads it; cause not traced. Use FLAC. Decoding is fine. The player always reads float and clips itself: libsndfile's 16-bit reads make loud MP3s wrap and click, and leave float WAVs nearly silent. Limits: 512 tracks, Latin-1 titles, volume keys only while the app is open, nothing remembered across a shell restart. Tests: `native/player/tests/test_player.c` against ALSA's `null` device; the phone has no `make`, so compile as in its Makefile. Measured with the app open and playing: shell ~24 % of a core; closed on the home screen: ~11 %.

**Files**: `native/filesd/` = web server, a separate program so that network parsing stays out of the root shell. `apps/files/app.py` starts it on "start sharing" (`Popen`, not a service: off at boot) and reads its status lines non-blocking in `key()` and `background()`; format in `trend/apps/files.h`, screen in `src/apps/files/`. Starts as root to bind :80, chowns the shared folders to user `trendfiles`, then setuid with no groups and NO_NEW_PRIVS, so with `ANDROID_PARANOID_NETWORK` it can accept but not open new sockets. Ends with its parent (PDEATHSIG, EPIPE), on SIGTERM, after 30 idle min, or after 10 wrong PINs. One thread + one request per connection (`Connection: close`), max 16. Uploads go to `/data/.filesd-tmp`, then fsync + rename, so a broken one never appears. Paths are walked a component at a time with O_NOFOLLOW. Reach it on Wi-Fi or USB. **Open each shared folder fresh with `openat(root, ".")`, never dup: a dup shares its read position, so listings came back empty** (only on the phone, where the startup chown had read to the end). Measured on the phone: 2.9 MB/s up, 5.1 MB/s down over Wi-Fi, ~0.5 MB RSS. Page: `overlay/usr/local/share/trendos/files/index.html`, read at start.

**Icon shading**: the shared light sits on one side, so flat-fronted icons (Files, SSH) go nearly dark at one end of the launcher sway. Mean shade of 12 drops to ~3. Not fixed: a change there affects every icon.

**Spotify** (shelved): go-librespot works for browsing/login, but every track fails `aes key code 1` (Spotify refuses librespot clients; workaround = DRM circumvention, not doing it). Code kept (`apps/spotify/`, `etc/init.d/spotify`, `tools/spotify/`). Revive: import in `apps/__init__.py`, re-add Entry, `SPOTIFY=1 tools/deploy.sh`.
